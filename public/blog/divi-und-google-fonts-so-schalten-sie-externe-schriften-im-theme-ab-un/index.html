Divi bringt eine große Auswahl an Schriftarten mit, und viele davon werden standardmäßig von Google-Servern geladen. Wer Divi Google Fonts deaktivieren möchte, stößt schnell auf mehrere Stellen, an denen Einstellungen nötig sind: Theme-Optionen, Divi Builder, Child-Theme und Plugins. Dieser Beitrag führt Schritt für Schritt durch die Divi-spezifischen Einstellungen und zeigt, wie Sie anschließend prüfen, ob noch Anfragen an fonts.googleapis.com laufen.

Zur rechtlichen Einordnung nur so viel: Beim Laden externer Schriften wird die IP-Adresse der Besucher an Google übertragen. Hintergründe dazu finden Sie im Beitrag zum Urteil des Landgerichts München. Hier geht es um die praktische Umsetzung. Dieser Text ist keine Rechtsberatung.

Warum Divi so oft Google Fonts lädt

Divi ist ein Theme mit integriertem Visual Builder. Sobald Sie in einem Modul eine Google-Schrift auswählen, wird sie über Googles Server eingebunden. Auch die Standardeinstellungen des Themes können Schriften nachladen, etwa die Schrift für Überschriften und Fließtext in den Theme-Anpassungen. Hinzu kommen Schriften, die in einzelnen Modulen, in Layout-Paketen aus der Divi-Bibliothek oder in Zusatz-Plugins hinterlegt sind. Ein einziges Häkchen reicht deshalb selten aus.

Schritt 1: Google Fonts in den Divi-Theme-Optionen abschalten

Je nach Divi-Version finden Sie die relevante Einstellung an leicht unterschiedlichen Stellen. Orientieren Sie sich an diesem Weg:

  • Im WordPress-Backend zu Divi → Theme-Optionen gehen.
  • Den Reiter Allgemein öffnen.
  • Nach der Option zur Google-Fonts-Unterstützung suchen (in neueren Versionen „Google Fonts aktivieren“ bzw. ähnlich benannt) und diese ausschalten.
  • Änderungen speichern.

Hinweis: Die genaue Bezeichnung kann sich zwischen Versionen unterscheiden. Prüfen Sie daher Ihre installierte Divi-Version. Ist die Option vorhanden, lädt Divi die Google-Schriften nicht mehr über die Google-Server nach. Zusätzlich sollten Sie im selben Bereich die Option für das statische CSS-Datei-Caching im Blick behalten. Leeren Sie nach jeder Änderung den Divi-Cache.

Schritt 2: Schriften im Divi Builder und in Vorlagen prüfen

Auch wenn die globale Option aus ist, können einzelne Elemente noch auf eine Google-Schrift verweisen. Gehen Sie so vor:

Globale Schriften im Theme Customizer

Unter Design → Customizer → Allgemeine Einstellungen → Typografie legen Sie Schrift für Überschriften und Text fest. Stellen Sie hier eine Systemschrift oder Ihre lokal hochgeladene Schrift ein.

Module im Divi Builder

Öffnen Sie wichtige Seiten im Builder und kontrollieren Sie in Textmodulen, Buttons, Menüs und Kopfzeilen den Reiter Design → Text/Schrift. Jedes Modul, in dem noch eine Google-Schrift ausgewählt ist, kann die Anfrage wieder auslösen. Auch im Theme Builder (Kopfzeile, Fußzeile, Beitragsvorlagen) lohnt sich der Blick.

Voreinstellungen und Layouts

Divi-Voreinstellungen (Presets) und importierte Layouts enthalten oft eigene Schriftangaben. Ändern Sie dort die Schrift oder passen Sie die Preset-Einstellungen an, sonst taucht die Google-Schrift an vielen Stellen erneut auf.

Schritt 3: Lokale Schriften einbinden

Ohne Google-Server brauchen Sie Alternativen. Zwei Wege bieten sich an:

  • Systemschriften: Sie liegen bereits auf dem Gerät der Besucher, es wird nichts nachgeladen. Das ist die einfachste Lösung.
  • Eigene Schriftdateien: Laden Sie die Schriften in einem webtauglichen Format (etwa WOFF2) auf Ihren eigenen Server und binden Sie sie per @font-face ein. Beachten Sie dabei die Lizenz der jeweiligen Schrift.

Divi erlaubt im Builder den Upload eigener Schriften über die Schriftauswahl („Hochladen“). Die hochgeladenen Dateien werden dann von Ihrer Domain ausgeliefert. Alternativ tragen Sie das @font-face-CSS in ein Child-Theme oder unter Divi → Theme-Optionen → Benutzerdefiniertes CSS ein. Eine ausführliche technische Anleitung zum Download und zur Einbindung steht im Beitrag Google Fonts selbst hosten.

Schritt 4: Kontrolle mit den Browser-Entwicklertools

Erst die Messung zeigt, ob wirklich keine Verbindung mehr zu Google besteht. So prüfen Sie es in Chrome, Firefox oder Edge:

  • Die Seite in einem privaten Fenster öffnen und mit F12 die Entwicklertools starten.
  • Den Reiter Netzwerk (Network) wählen.
  • Die Option „Cache deaktivieren“ aktivieren und die Seite mit Strg+Shift+R neu laden.
  • Im Filterfeld nach fonts.googleapis.com und fonts.gstatic.com suchen.

Bleibt die Liste leer, wird auf dieser Seite nichts von diesen Domains geladen. Erscheinen Treffer, klicken Sie darauf: Die Spalte „Initiator“ zeigt, welche Datei oder welches Skript die Anfrage auslöst. Das führt Sie oft direkt zu einem Plugin oder Modul.

Prüfen Sie nicht nur die Startseite, sondern auch Unterseiten, Blogbeiträge, Kontaktformulare und Seiten mit besonderen Layouts. Testen Sie außerdem mit leerem Cache und eingeloggt wie ausgeloggt, da der Visual Builder eigene Ressourcen laden kann.

Wenn trotzdem Anfragen laufen: typische Ursachen

  • Caching: Alte, zusammengefasste CSS-Dateien enthalten noch die Google-Schrift. Divi-Cache, Plugin-Cache und ggf. CDN leeren.
  • Child-Theme: Ein @import in der style.css oder ein wp_enqueue_style in der functions.php verweist noch auf Google.
  • Plugins: Kontaktformulare, Slider, Social-Feeds oder Zusatzmodule für Divi laden eigene Schriften nach.
  • Eingebettete Inhalte: Karten oder Videos können weitere Verbindungen zu Drittanbietern aufbauen. Das sind dann andere Domains und ein eigenes Thema.
  • Optimierungs-Plugins: Manche Tools speichern Schriften zwischen oder fügen sie wieder ein. Prüfen Sie deren Font-Einstellungen.

Dauerhaft im Blick behalten

Nach Theme-Updates, neuen Layouts oder Plugin-Installationen kann sich die Situation ändern. Wiederholen Sie die Netzwerkprüfung daher in regelmäßigen Abständen und dokumentieren Sie den Stand mit Datum und Screenshot. Wie eine strukturierte Kontrolle aussehen kann, beschreibt der Beitrag Google Fonts DSGVO-Check.

Fazit

Wer bei Divi Google Fonts deaktivieren will, sollte nicht bei einer einzelnen Option stehen bleiben: Theme-Optionen, Customizer, Builder-Module, Presets, Child-Theme und Plugins gehören zusammen betrachtet. Lokale oder Systemschriften ersetzen die externen Schriften, und die Netzwerkansicht der Entwicklertools liefert den Beleg, ob noch Anfragen an Google gehen. Eine absolute Gewissheit für jede Konstellation kann keine Anleitung bieten. Bei Unsicherheiten zur rechtlichen Bewertung wenden Sie sich an eine fachkundige Stelle.
