Google Fonts selbst hosten: Schritt-für-Schritt vom Google-Server zur eigenen Installation

Wer seinen Website-Check durchführt und ein rotes Ergebnis bei Google Fonts erhält, steht vor der praktischen Frage: Wie binde ich die Schriftarten lokal ein, ohne sie weiterhin von Google-Servern zu laden? Die technische Umsetzung ist weniger kompliziert als viele befürchten. In dieser Anleitung erfahren Sie konkret, wie Sie Google Fonts selbst hosten und welche Schritte für eine saubere Implementierung notwendig sind.

Warum überhaupt selbst hosten statt Google-Server nutzen?

Wenn Sie Google Fonts direkt von den Google-Servern einbinden, stellt jeder Seitenaufruf Ihrer Website eine Verbindung zu fonts.googleapis.com oder fonts.gstatic.com her. Dabei werden IP-Adressen der Besucher an Google übermittelt. Da IP-Adressen personenbezogene Daten darstellen, ist diese Übermittlung datenschutzrechtlich relevant und erfordert eine Rechtsgrundlage.

Beim Self-Hosting laden die Schriftdateien direkt von Ihrem eigenen Server. Es findet keine Verbindung zu Google statt, keine IP-Adressen werden an Dritte übermittelt. Die rechtlichen Hintergründe und Konsequenzen, die durch bekannte Gerichtsurteile entstanden sind, werden ausführlich im Artikel zum Landgericht München Google Fonts Urteil behandelt.

Schritt 1: Die richtigen Schriftdateien identifizieren und herunterladen

Zunächst müssen Sie herausfinden, welche Google Fonts Ihre Website aktuell verwendet. Öffnen Sie den Quellcode Ihrer Website und suchen Sie nach Verweisen auf fonts.googleapis.com. Der Link sieht typischerweise so aus:

<link href="https://fonts.googleapis.com/css2?family=Roboto:wght@400;700&display=swap" rel="stylesheet">

Notieren Sie die Schriftfamilie und die benötigten Schriftschnitte. Im Beispiel wären das Roboto in den Stärken 400 (regular) und 700 (bold).

Download der Font-Dateien

Es gibt verschiedene Wege, die Dateien zu beschaffen:

  • Direkter Download über die offizielle Google Fonts Website mit anschließendem manuellen Download der Schriftdateien
  • Nutzung von Helper-Tools wie dem Google Webfonts Helper, der die benötigten Dateien zusammenstellt und die CSS-Deklarationen generiert
  • Klonen des gesamten Google Fonts Repositories, wenn Sie viele verschiedene Schriften benötigen

Der Google Webfonts Helper ist für die meisten Anwender die praktikabelste Lösung. Geben Sie dort die gewünschte Schriftfamilie ein, wählen Sie die benötigten Schriftschnitte aus und laden Sie das generierte Paket herunter. Sie erhalten eine ZIP-Datei mit den Schriftdateien in verschiedenen Formaten sowie passendem CSS-Code.

Schritt 2: Font-Dateien auf den eigenen Server hochladen

Erstellen Sie auf Ihrem Webserver ein eigenes Verzeichnis für Schriftarten. Eine sinnvolle Struktur könnte so aussehen:

/fonts/roboto/

Laden Sie die heruntergeladenen Schriftdateien in dieses Verzeichnis. Sie benötigen mindestens das WOFF2-Format, da dies von allen modernen Browsern unterstützt wird und die kleinste Dateigröße bietet. WOFF kann als Fallback für ältere Browser dienen.

Achten Sie darauf, dass die Dateien über HTTP erreichbar sind. Testen Sie dies, indem Sie die URL direkt im Browser aufrufen, etwa: https://ihre-domain.de/fonts/roboto/roboto-v30-latin-regular.woff2

Schritt 3: CSS-Deklaration anpassen und einbinden

Jetzt erstellen Sie die CSS-Regeln, die dem Browser mitteilen, wo er die Schriftdateien findet. Erstellen Sie eine neue CSS-Datei, etwa fonts.css, oder fügen Sie den Code Ihrer bestehenden Stylesheet-Datei hinzu.

Eine typische @font-face-Deklaration für selbst gehostete Google Fonts sieht so aus:

@font-face {
  font-family: 'Roboto';
  font-style: normal;
  font-weight: 400;
  font-display: swap;
  src: url('/fonts/roboto/roboto-v30-latin-regular.woff2') format('woff2'),
       url('/fonts/roboto/roboto-v30-latin-regular.woff') format('woff');
}

Wiederholen Sie diese Deklaration für jeden benötigten Schriftschnitt. Für Roboto Bold mit font-weight 700 erstellen Sie eine entsprechende zweite @font-face-Regel mit angepasstem font-weight und anderen Dateinamen.

Die font-display-Eigenschaft richtig setzen

Die Eigenschaft font-display: swap sorgt dafür, dass der Browser zunächst eine Ersatzschrift anzeigt und zur eigentlichen Schrift wechselt, sobald diese geladen ist. Dies verhindert unsichtbare Texte während des Ladevorgangs und verbessert die Benutzererfahrung.

Schritt 4: Alte Google-Fonts-Einbindung entfernen

Dieser Schritt ist entscheidend: Entfernen Sie alle Verweise auf fonts.googleapis.com und fonts.gstatic.com aus Ihrem HTML-Code. Suchen Sie sowohl im Header-Bereich als auch in Stylesheets und Template-Dateien nach entsprechenden Einträgen.

Typische Fundstellen:

  • Link-Tags im HTML-Head
  • @import-Anweisungen in CSS-Dateien
  • Einträge in Theme-Einstellungen bei Content-Management-Systemen
  • Preload-Tags für Performance-Optimierung

Prüfen Sie nach der Entfernung, ob Ihre Website die Schriftarten korrekt darstellt. Leeren Sie gegebenenfalls den Browser-Cache für einen aussagekräftigen Test.

Schritt 5: Implementierung in gängigen CMS-Systemen

WordPress

In WordPress können Sie die Schriftdateien in ein Unterverzeichnis Ihres Themes hochladen, etwa /wp-content/themes/ihr-theme/fonts/. Die CSS-Deklarationen fügen Sie in die style.css des Themes oder in eine separate CSS-Datei ein, die Sie über die functions.php einbinden.

Zusätzlich müssen Sie verhindern, dass WordPress oder installierte Plugins Google Fonts nachladen. Viele Cache- und Performance-Plugins bieten Optionen, um externe Schriftarten zu deaktivieren. Alternativ können Sie über die functions.php Google-Font-Anfragen herausfiltern.

TYPO3, Joomla und andere Systeme

Das Grundprinzip bleibt identisch: Schriftdateien in einen öffentlich zugänglichen Ordner laden, CSS-Deklarationen erstellen und alte Einbindungen entfernen. Die genaue Umsetzung hängt von der Template-Struktur des jeweiligen Systems ab. Prüfen Sie auch installierte Extensions auf automatische Google-Fonts-Einbindungen.

Schritt 6: Technische Kontrolle nach der Umstellung

Nach der Implementierung sollten Sie überprüfen, ob tatsächlich keine Verbindungen mehr zu Google-Servern hergestellt werden. Nutzen Sie dafür die Entwicklertools Ihres Browsers:

  • Öffnen Sie die Netzwerkanalyse (Network-Tab)
  • Laden Sie Ihre Website neu
  • Filtern Sie nach "fonts" oder suchen Sie nach "googleapis"
  • Es sollten keine Anfragen an Google-Domains erscheinen

Für eine umfassende Überprüfung können Sie auch einen Google Fonts DSGVO Check durchführen, der automatisiert externe Schriftarten-Einbindungen erkennt.

Performance-Aspekte beim Self-Hosting

Selbst gehostete Schriftarten können die Ladezeit Ihrer Website beeinflussen. Achten Sie auf folgende Optimierungen:

  • Verwenden Sie nur die Schriftschnitte, die Sie tatsächlich benötigen
  • Nutzen Sie ausschließlich WOFF2-Dateien für moderne Browser
  • Implementieren Sie Preload-Anweisungen für kritische Schriftdateien
  • Aktivieren Sie Server-Kompression für Schriftdateien
  • Setzen Sie geeignete Cache-Header, damit Browser die Dateien lokal speichern

Ein Preload-Tag im HTML-Head sieht so aus:

<link rel="preload" href="/fonts/roboto/roboto-v30-latin-regular.woff2" as="font" type="font/woff2" crossorigin>

Häufige Fehlerquellen und Lösungen

Wenn die Schriftarten nach der Implementierung nicht korrekt dargestellt werden, liegt meist eine dieser Ursachen vor:

  • Falsche Pfadangaben: Prüfen Sie, ob die URL in der CSS-Deklaration wirklich auf die hochgeladenen Dateien zeigt
  • CORS-Probleme: Schriftdateien benötigen das crossorigin-Attribut, wenn sie von einer Subdomain geladen werden
  • Fehlende Schriftschnitte: Wenn Sie font-weight oder font-style verwenden, für die keine @font-face-Regel existiert, greift der Browser auf Systemschriften zurück
  • Cache-Probleme: Alte externe Schriftarten können noch im Browser-Cache liegen
  • Doppelte Einbindung: Manche Plugins oder Themes binden Google Fonts automatisch ein, selbst wenn Sie sie entfernt haben

Datenschutzrechtliche Einordnung nach der Umstellung

Wenn Sie Google Fonts selbst hosten, erfolgt die Darstellung der Schriftarten vollständig über Ihre eigene technische Infrastruktur. Es werden keine personenbezogenen Daten an Drittanbieter übermittelt, keine Cookies gesetzt und keine externen Anfragen ausgelöst. Dieser Ansatz ist Teil einer umfassenden DSGVO-Konformität, die Sie systematisch mit einem Website-Selbstcheck überprüfen können.

Beachten Sie, dass die Schriftarten selbst weiterhin unter der Open-Source-Lizenz von Google stehen. Sie dürfen sie frei verwenden, müssen aber keine Lizenzgebühren zahlen oder bestimmte Lizenztexte auf Ihrer Website einbinden.

Fazit: Technische Umsetzung mit überschaubarem Aufwand

Google Fonts selbst zu hosten erfordert keine tiefgreifenden Programmierkenntnisse. Mit den beschriebenen Schritten – Download der Dateien, Upload auf den Server, Anpassung der CSS-Deklarationen und Entfernung der alten Einbindung – lässt sich die Umstellung in überschaubarer Zeit umsetzen. Die technische Kontrolle nach der Implementierung stellt sicher, dass tatsächlich keine externen Verbindungen mehr bestehen. So schaffen Sie eine Grundlage für eine datenschutzkonforme Website-Gestaltung, ohne auf ansprechende Typografie verzichten zu müssen.
